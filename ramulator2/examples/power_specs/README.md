# Generated DRAM power specifications

These JSON files are generated by `ramulator.power.HBM34PowerModel` or
`ramulator.power.LPDDRPowerModel`. Do not
edit organization or timing fields manually: the associated Python example
overwrites a file whenever its resolved Ramulator DRAM configuration changes.

| Simulation configuration | Generated DRAMPower memspec |
| --- | --- |
| `examples/HBM3_image_config.py` | `HBM3_image_config.generated.json` |
| `examples/HBM3E_image_config.py` | `HBM3E_image_config.generated.json` |
| `examples/HBM4_image_config.py` | `HBM4_image_config.generated.json` |
| `examples/HBM4_example_config.py` | `HBM4_example_config.generated.json` |
| `examples/example_config.py` | `example_config.generated.json` |
| `examples/LPDDR5_example_config.py` | `LPDDR5_example_config.generated.json` |
| `examples/LPDDR6_example_config.py` | `LPDDR6_example_config.generated.json` |

Changing a trace changes the issued command stream and therefore the measured
energy without changing the memspec. Changing `ORG_PRESET`, `TIMING_PRESET`,
or a DRAM override regenerates the corresponding memspec before simulation.

Organization and timing are exact resolved Ramulator values. Electrical HBM
parameters are estimates derived from the repository's HBM-Power profiles;
each JSON file records the source, method, and validation status in
`modelMetadata`.

LPDDR electrical/impedance inputs use the bundled exploratory LPDDR fixtures,
not vendor-calibrated parameters. See [LPDDR_POWER.md](../LPDDR_POWER.md) for
public references, configurable policies, and limitations. Generated LPDDR
organization, timing, WCK mode, payload size, and capacity follow the associated
Python configuration; changing only a trace changes commands and energy, not
the device electrical parameters.
